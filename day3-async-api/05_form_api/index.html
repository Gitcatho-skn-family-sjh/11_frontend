DAY 3 · FETCH 05

검색 폼의 입력을 API 결과 카드로 연결하기

입력 검증, 요청 설정, API 호출, 결과 렌더링의 책임을 함수로 나눈다.
페이지를 새로고침하지 않고 검색 상태와 결과 카드만 갱신한다.

SEARCH FLOW

하나의 검색을 다섯 역할로 나누어 읽기

  • validateQuery() — 입력 검증
    앞뒤 공백을 제거하고 빈 검색어인지 확인한다.
  • createRequestOptions() — 요청 설정
    POST 메서드, JSON 헤더, 전송할 본문을 만든다.
  • requestBooks() — 서버 통신
    fetch로 요청하고 HTTP 상태와 응답 JSON을 확인한다.
  • renderSearchResults() — 결과 출력
    객체 배열을 제목·저자·식별 정보가 있는 카드로 만든다.
  • setSearchState() — 화면 상태
    loading, success, empty, error를 서로 다른 메시지로 표시한다.

한 함수가 모든 작업을 맡으면 어디에서 문제가 생겼는지 찾기 어렵다.
입력, 통신, 화면의 경계를 나누면 Django나 FastAPI로 서버를 교체해도 각 역할을 추적하기 쉽다.

FORM EVENT

click이 아니라 form의 submit 이벤트를 처리한다

async function handleSubmit(event) {
  event.preventDefault();

  const query = validateQuery();
  if (query === "") {
    // 안내를 표시하고 fetch는 호출하지 않는다.
    return;
  }

  // 검증을 통과한 뒤 요청한다.
}
  • submit 이벤트는 버튼 클릭과 Enter 입력을 함께 처리한다. 검색 버튼에 click만 연결하면 키보드 제출 흐름을 놓치기 쉽다.
    폼 자체에 submit 이벤트를 연결하면 두 동작이 같은 함수로 들어온다.
  • preventDefault()는 기본 페이지 이동을 막는다. 브라우저가 폼을 제출해 새 문서를 여는 대신 JavaScript가 비동기 요청을 담당한다.
    그래서 현재 페이지의 검색 결과 영역만 바뀐다.
  • 빈 검색어는 요청 전에 차단한다. trim() 결과가 빈 문자열이면 Network에 요청을 만들지 않는다.
    브라우저 검사와 별개로 실제 서버도 입력을 다시 검증해야 한다.

POST JSON

JavaScript 객체를 전송용 JSON 문자열로 바꾼다

const options = {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    query: query,
    mode: mode.value
  })
};

const response =
  await fetch(lessonApiUrl("/api/books/search"), options);
  • method: "POST"는 요청 방식을 서버 계약에 맞춘다.
    모든 검색이 POST인 것은 아니며 사용할 API 명세를 따라야 한다.
  • Content-Type은 보내는 본문이 JSON임을 서버에 알린다.
    응답 형식을 지정하는 속성과 혼동하지 않는다.
  • JSON.stringify()는 객체를 HTTP 본문에 넣을 문자열로 바꾼다.
    응답의 response.json()은 반대로 JSON 텍스트를 JavaScript 값으로 해석한다.

UI STATE

사용자가 지금 무슨 일이 일어나는지 알 수 있어야 한다

loading

요청 중이라는 메시지를 보여 주고 입력과 버튼을 잠가 중복 제출을 막는다.

success / empty

검색된 카드 수를 알리거나 정상적으로 0건임을 분명히 표시한다.

error

이전 결과를 지우고 HTTP 또는 연결 오류를 표시한 뒤 다시 시도할 수 있게 한다.

finally는 성공과 실패 모두에서 실행된다.
여기서 버튼과 입력을 복구하면 오류가 발생한 뒤에도 사용자가 다시 검색할 수 있다.

CODE & DEMO

검색어를 보내고 실무형 결과 카드를 만들기

try {
  const options = createRequestOptions(query);
  const books = await requestBooks(options);
  renderSearchResults(query, books);
} catch (error) {
  results.replaceChildren();
  setSearchState("error", describeError(error));
} finally {
  setBusy(false);
}

검색 전이다.

  • 화면을 검색한다. 제목이나 저자에 검색어가 포함된 책이 카드로 표시된다.
    제목·저자·도서 ID는 모두 textContent 경로로 출력한다.
  • 존재하지 않는 단어를 검색한다. 요청 성공과 검색 결과 0건을 구분해 empty 상태를 표시한다.
    0건은 서버 오류가 아니다.
  • 느린 응답을 선택한다. 기다리는 동안 중복 제출이 막히고 aria-busy가 true로 바뀐다.
    완료되면 finally가 입력과 버튼을 복구한다.
  • 오류 응답을 선택한다. HTTP 503을 오류 상태로 보여 주고 이전 카드는 지운다.
    정상 응답으로 바꾼 뒤 같은 페이지에서 다시 검색할 수 있다.
