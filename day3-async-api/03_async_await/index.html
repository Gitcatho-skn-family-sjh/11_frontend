DAY 3 · ASYNC 03

Promise와 완료된 값을 눈으로 비교하기

일반 값, 아직 처리 중인 Promise, await 뒤의 완료 값을 한 화면에서 비교한다.
문법을 외우기 전에 어떤 값이 언제 생기는지 확인한다.

VALUE

바로 받는 값과 나중에 받는 값은 다르다

일반 계산은 호출한 자리에서 결과를 바로 사용할 수 있다.
서버 요청처럼 시간이 필요한 작업은 지금 결과 대신 나중 결과를 담을 약속 객체를 먼저 돌려준다.

일반 값

const value = "완료";

다음 줄에서 바로 문자열을 읽을 수 있다.

Promise 객체

const promise = requestMessage();

호출 직후에는 결과 문자열이 아니라 Promise를 받는다.

const directValue = "바로 받은 문자열";
const promise = requestMessage(false);

console.log(directValue); // 바로 받은 문자열
console.log(promise);     // Promise 객체

PROMISE

Promise는 비동기 결과의 진행 상태를 표현한다

  • pending은 기다리는 중이다. 성공 값과 실패 이유가 아직 정해지지 않은 상태이다.
    이 상태의 Promise 자체를 문자열처럼 사용할 수는 없다.
  • fulfilled는 성공한 상태이다. 작업이 끝나 결과 값을 받을 수 있다.
    이번 제공 함수는 성공하면 문자열을 결과로 전달한다.
  • rejected는 실패한 상태이다. 정상 값 대신 오류 이유가 정해진다.
    네트워크 실패뿐 아니라 우리가 만든 오류도 이 경로로 처리할 수 있다.

requestMessage() 안의 Promise 생성 코드는 제공되어 있다.
학생은 Promise를 직접 만드는 것보다 이미 반환된 Promise의 결과를 사용하는 연습에 집중한다.

ASYNC / AWAIT

await는 현재 async 함수의 다음 줄만 기다린다

async function readMessage() {
  const message = await requestMessage(false);
  console.log(message);
}

const returnedValue = readMessage();
console.log(returnedValue instanceof Promise); // true
  • async는 함수 안에서 await를 사용할 수 있게 한다. async 함수가 문자열을 return해도 호출한 쪽에는 Promise가 돌아간다.
    그래서 예제에서는 async 함수의 반환값도 Promise인지 확인한다.
  • await는 Promise가 끝날 때까지 현재 함수의 다음 줄을 미룬다. 성공하면 완료 값이 변수에 들어간다.
    브라우저 전체를 멈추는 명령은 아니다.
  • 다른 이벤트는 계속 처리된다. 결과를 기다리는 동안 옆의 카운터 버튼을 누를 수 있다.
    이 동작으로 화면 전체가 멈추지 않았음을 직접 확인한다.

    ORDER

    화면에서 확인할 실행 순서

    • 함수가 Promise를 바로 받는다.
      요청 결과 문자열은 아직 준비되지 않았다.
    • 함수 밖과 다른 이벤트가 계속 실행된다.
      카운터 버튼도 정상적으로 반응한다.
    • Promise가 끝나면 await 다음 줄이 실행된다.
      성공 값 또는 실패 이유를 화면에 표시한다.
    • finally가 공통 정리를 수행한다.
      성공 여부와 관계없이 실행 버튼을 복구한다.
