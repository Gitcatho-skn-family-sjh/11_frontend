DAY 3 · DATA & FETCH 07

Fetch로 AI 응답을 화면에 표시한다

질문을 JSON 본문으로 보내고 text 또는 JSON 응답을 읽는다.
같은 답변도 응답 형식에 따라 처리 코드가 달라지는 이유를 확인한다.

POST REQUEST

질문 객체를 전송 가능한 JSON 문자열로 바꾼다

질문은 URL에 붙이지 않고 POST 요청의 body에 넣는다.
JavaScript 객체를 그대로 보낼 수 없으므로 JSON.stringify로 JSON 문자열을 만든다.

const endpoint = lessonApiUrl(`/api/openai/${responseFormat.value}`);
const options = {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ prompt, mode: aiMode.value })
};
const response = await fetch(endpoint, options);
  • 입력은 전송 전에 검사한다. 앞뒤 공백을 제거한 질문이 비어 있으면 fetch를 호출하지 않는다.
    서버도 1~500자 규칙을 다시 검사하므로 브라우저 검사만 신뢰하지 않는다.
  • Content-Type은 요청 본문의 형식을 알린다. 서버는 이 헤더를 보고 body를 JSON 객체로 해석한다.
    응답 형식은 선택한 endpoint가 결정하며 요청 헤더 하나로 text와 JSON이 자동 전환되지 않는다.
  • mock과 live의 브라우저 코드는 같다. mode 값만 달라지고 요청·상태·DOM 처리 흐름은 유지된다.
    먼저 mock으로 완성한 뒤 필요할 때만 live 연결을 확인한다.

TEXT OR JSON

응답 본문은 한 번만, 약속된 형식으로 읽는다

/api/openai/text는 일반 문자열을, /api/openai/json은 속성을 가진 객체를 반환한다.
Response 객체 자체가 답변은 아니며, 본문 읽기 메서드를 await 해야 실제 값을 얻는다.

if (formatSelect.value === "text") {
  answerText = await response.text();
} else {
  rawData = await response.json();
  answerText = rawData.text;
}
  • text()는 본문 전체를 문자열로 읽는다. 바로 textContent에 넣을 수 있지만 출처나 모델 같은 값을 별도 속성으로 구분하기 어렵다.
    이 예제의 text 응답에는 출처 표식도 문자열 안에 포함된다.
  • json()은 JSON 텍스트를 객체로 해석한다. data.text, data.source, data.model처럼 각 값을 따로 사용할 수 있다.
    화면 요소가 여러 종류의 정보를 나눠 보여 줄 때 적합하다.
  • 한 응답 본문을 두 번 읽지 않는다. text를 읽은 뒤 같은 response에서 json을 다시 호출하면 실패한다.
    endpoint의 계약을 알고 조건에 맞는 메서드 하나만 선택한다.

요청 전이다.

AI 응답 -

받은 원본 보기
아직 받은 응답이 없다.
  • text 선택은 문자열을 그대로 표시한다. badge에 text/plain이 보이고 원본 보기에도 같은 문자열이 표시된다.
    문자열에 포함된 줄바꿈은 화면에서 읽을 수 있도록 유지한다.
  • JSON 선택은 객체에서 필요한 값을 꺼낸다. 답변은 text에, 출처와 모델은 보조 정보에 배치한다.
    원본 보기에서는 객체가 가진 세 속성을 함께 확인한다.
  • 오류이면 이전 답변을 숨긴다. live 실행 조건이 없으면 503 안내를 보여 주고 입력과 버튼을 복구한다.
    mock으로 바꾸어 다시 요청하면 페이지를 새로 열지 않고도 정상 상태로 돌아온다.

API KEY

OpenAI 키와 모델 이름은 server.py의 환경변수로 관리한다

live 요청에서도 app.js는 OpenAI 주소와 API 키를 직접 사용하지 않는다.
server.py가 OPENAI_API_KEY와 OPENAI_MODEL을 읽어 Responses API에 요청한다.

  • 브라우저 코드는 사용자에게 전달된다. 키를 app.js의 상수나 HTML 속성에 넣으면 개발자 도구에서 확인할 수 있다.
    키는 서버 프로세스에만 설정하고 저장소, HTML, JavaScript, 화면 응답에 포함하지 않는다.
  • live는 명시적으로 허용한다. --allow-live-api 없이 실행하면 키가 설정되어 있어도 외부 요청을 보내지 않는다.
    실습 중 예상하지 못한 호출과 비용을 줄이기 위한 경계이다.
  • 출력 길이에도 상한을 둔다. server.py는 live 요청에 max_output_tokens: 300을 넣어 수업 범위를 넘는 긴 생성을 제한한다.
    토큰 수는 글자 수와 정확히 같지 않으며, 이 값은 최대 출력량을 제한하는 안전장치이다.
  • 서버는 외부 오류 원문을 숨긴다. 브라우저에는 재시도 가능한 한국어 안내만 반환한다.
    외부 응답 전체에는 운영 정보가 포함될 수 있으므로 그대로 중계하지 않는다.

OpenAI 공식 개발자 빠른 시작에서 서버 측 API 요청 흐름을 확인할 수 있다.
API 키 안전 지침에 따라 키를 브라우저 코드나 저장소에 포함하지 않는다.
