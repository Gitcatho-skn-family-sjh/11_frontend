Day 104입력 양식

HTML · FORM

입력칸은 설명·값 이름·제출 버튼과 함께 동작한다

form 안에서 label, input, button을 연결해
사용자가 무엇을 입력하고 어떤 값을 제출하는지 명확하게 만든다.

for ↔ idnameinput typebutton type

A FIELD IS A SET

입력칸 하나는 보이는 설명과 실제 입력 요소로 구성된다

label은 사용자가 입력해야 할 내용을 글자로 알려 준다.
label for="display-name"과 input id="display-name"처럼 같은 값을 사용하면 설명 글자를 눌러도 입력칸으로 초점이 이동한다.

placeholder는 입력 예시일 뿐 이름표를 대신하지 못한다.
사용자가 값을 입력하면 placeholder는 사라지지만 label은 계속 남아 입력 목적을 알려 준다.
따라서 실제 양식에서는 label을 생략하지 않는다.

  • label: 입력칸이 어떤 값을 받는지 눈에 보이는 이름으로 설명한다.
    입력값을 지운 뒤에도 목적이 남아 있어야 하므로 placeholder 대신 항상 제공한다.
  • for와 id: 두 속성에 정확히 같은 문자열을 쓰면 label을 클릭했을 때 연결된 input에 초점이 이동한다.
    철자 하나라도 다르면 화면은 보여도 두 요소의 연결은 끊어진다.
  • name: 양식을 제출할 때 각 값을 구분하는 전달 이름이다.
    사용자가 보는 label 문장과 서버가 읽는 name은 목적이 다르므로 둘을 같은 개념으로 혼동하지 않는다.
  • type과 placeholder: type은 받을 값의 종류와 기본 검증 방식을 정하고 placeholder는 입력 예시만 보여 준다.
    이메일에는 email, 연락처에는 tel처럼 값의 성격에 맞는 type을 고른다.

for와 id

화면에서 label과 한 input을 연결한다.
같은 문자열을 사용해야 한다.

name

제출할 때 값을 구분하는 이름이다.
서버는 이 파라미터 이름으로 입력값을 구분한다.

EXAMPLE

설명 글자와 입력칸을 연결한다

수강 신청 양식의 핵심 구조HTML 
<form action="" method="get">
  <label for="display-name">이름</label>
  <input
    id="display-name"
    name="display-name"
    type="text"
    placeholder="예: 김민지"
  >
  <label for="email">이메일</label>
  <input id="email" name="email" type="email" placeholder="name@example.com">
  <button type="submit">신청 내용 보내기</button>
</form>
수업에서 부를 이름을 입력한다.

‘이름’ 글자를 눌렀을 때 첫 입력칸의 커서가 깜빡이면 연결이 맞다.
두 입력칸은 서로 다른 id와 name을 사용하므로 브라우저와 제출받는 쪽이 값을 구분할 수 있다.

type="text"는 일반 글자를 받는다.
이메일 입력은 type="email"을 사용해 브라우저가 값의 형식을 도울 수 있다.
button type="submit"은 form의 값을 제출하는 버튼임을 분명히 한다.

for="name"인데 id="display-name"이면 연결되지 않는다

두 값은 비슷한 뜻이 아니라 정확히 같은 문자열이어야 한다.
label을 눌러 초점이 이동하지 않으면 먼저 for와 id를 글자 단위로 비교한다.

FROM BROWSER TO SERVER

name은 서버로 전달되는 파라미터의 이름이다

form을 제출하면 input에 입력한 값은 name 속성을 기준으로 구분되어 서버로 전달된다.
예를 들어 name="display-name"인 입력칸에 “민지”를 입력하면 서버에는 display-name=민지 형태의 데이터가 전달된다.

label은 사용자가 화면에서 읽는 설명이고, id는 label과 input을 연결하는 식별자이다.
name은 서버가 여러 입력값을 구분할 때 사용하는 파라미터의 이름이다.

같은 form 안에 input이 여러 개 있어도 각 input의 name이 다르면 서버는 전달된 값을 구분할 수 있다.
반대로 input에 name이 없으면 값을 입력했더라도 일반적인 form 제출 데이터에는 포함되지 않는다.

EXAMPLE

required와 type으로 브라우저의 기본 검증을 확인한다

  • required는 값이 비어 있으면 제출을 막는다.
    값 없이 사용하는 불리언 속성이므로 required="false"라고 적어도 속성이 존재하는 한 필수 입력으로 취급된다.
  • type="email"은 이메일 모양인지 검사하고, minlength는 사용자가 입력한 문자열의 최소 길이를 제한한다.
    실제로 존재하는 주소인지 또는 안전한 입력인지는 별도 문제이므로 서버 검증을 대체하지 않는다.
  • type="reset"은 폼을 처음 열었을 때의 기본값으로 되돌린다.
    기본값이 비어 있다면 입력칸도 다시 빈 상태가 된다.
<form method="get">
  <label for="contact-email">답장 받을 이메일</label>
  <input id="contact-email" name="replyTo" type="email" required>
  <label for="contact-subject">문의 제목</label>
  <input id="contact-subject" name="subject" minlength="3" required>
  <button type="submit">문의 보내기</button>
  <button type="reset">처음으로</button>
</form>

빈 상태에서 제출, abc를 이메일로 입력한 뒤 제출, 올바른 이메일과 두 글자 제목을 직접 입력한 뒤 제출을 차례로 비교한다.
브라우저가 입력 요소 가까이에 다른 안내를 표시한다. 모두 유효하면 현재 페이지의 URL에 replyTo와 subject가 붙는다.

EXAMPLE

라디오와 체크박스는 선택 방식과 전송값이 다르다

  • 같은 폼 안에서 name이 같은 radio들은 한 그룹이다.
    하나를 선택하면 기존 선택이 해제되며, 선택된 항목의 value가 전송된다.
  • checkbox는 여러 항목을 독립적으로 선택할 수 있다.
    동일한 name을 여러 번 사용하면 하나의 파라미터 이름으로 여러 선택값을 보낼 수 있다.
  • 선택되지 않은 checkbox·radio와 disabled 입력은 일반적인 폼 전송 데이터에 포함되지 않는다.
    checked는 처음 표시할 선택 상태이고, fieldset과 legend는 관련 입력의 묶음과 제목을 표현한다.
<form method="get">
  <fieldset>
    <legend>알림 주기</legend>
    <label><input type="radio" name="frequency" value="daily" checked> 매일</label>
    <label><input type="radio" name="frequency" value="weekly"> 매주</label>
  </fieldset>
  <label><input type="checkbox" name="channel" value="email"> 이메일</label>
  <label><input type="checkbox" name="channel" value="sms"> 문자</label>
  <button type="submit">설정 보내기</button>
</form>
알림 주기

매주와 두 알림 수단을 모두 선택하면 frequency=weekly, channel=email, channel=sms가 전송된다.
radio의 name을 서로 다르게 바꾸면 두 항목이 함께 선택될 수 있으므로, 그룹의 기준이 화면 위치가 아니라 이름임을 확인할 수 있다.
