CSS 06

겹치는 CSS 선언의 최종값을 정하는 순서

선택자가 맞는데 모양이 바뀌지 않는다면 다른 선언이 이기고 있을 수 있다.
캐스케이드·명시도·상속을 구분하면 무작정 규칙을 추가하지 않고 원인을 찾을 수 있다.

CASCADE

브라우저는 같은 요소의 같은 속성을 놓고 선언을 비교한다

  • 캐스케이드(cascade): 여러 곳에서 들어온 CSS 선언 중 최종적으로 사용할 값을 고르는 절차이다.
    브라우저 기본 스타일, 작성자가 연결한 CSS, 내부 style, 인라인 스타일이 모두 화면에 영향을 줄 수 있다.
  • 속성별 결정: 하나의 규칙 전체가 이기거나 지는 것이 아니다.
    color는 A 규칙, padding은 B 규칙에서 정해질 수 있다.
  • 이번 예제의 비교 범위: 애니메이션·전환·@scope 없이, 별도 레이어를 사용하지 않은 작성자 CSS를 비교한다.
    동일한 출처(origin)·중요도·레이어(layer) 조건에서는 선택자의 명시도를 비교하고, 그것도 같으면 이 예제에서는 나중 선언을 선택한다.
  • 항상 아래가 이기는 것은 아님: !important 등 중요도 차이는 명시도보다 먼저 고려된다.
    사용자 스타일·레이어·애니메이션·전환·scope의 세부 우선순위는 확장 주제이며, 단순한 ‘id > class > 태그’만으로 모든 CSS를 설명할 수 없다.

우선 “그 요소에 적용되는가?”를 선택자로 확인하고, “같은 속성에 경쟁하는 선언이 있는가?”를 확인한다.
이 페이지의 예제는 한 번에 비교 조건 하나씩만 바꾼다. 예제 카드의 여백과 기본 solid 테두리·색은 제공된 CSS를 사용하고, 표시한 코드에서는 비교할 선언에 집중한다.

EXAMPLE 1

비교 조건이 같으면 나중에 선언한 값이 적용된다

  • 같은 대상·같은 속성: 두 규칙 모두 같은 카드의 color를 지정한다.
  • 같은 명시도: 선택자가 완전히 같으므로 명시도 차이가 없다.
  • 소스 순서: 나중에 나온 주황색이 적용된다.
    외부 CSS가 여러 개라면 다운로드가 끝난 시간이 아니라 문서에 연결한 스타일시트와 그 안의 선언 순서를 본다.
.cascade-order .card { color: #0057d9; }
.cascade-order .card { color: #9b3f00; }

<div class="cascade-order">
  <p class="card">최종 글자색은 주황색</p>
</div>

최종 글자색은 주황색

두 규칙의 순서를 바꾸면 최종 글자색도 파란색으로 바뀐다.
선택자를 더 복잡하게 만들 필요 없이 기존 선언의 위치부터 확인한다.

EXAMPLE 2

나중 규칙이 이전 규칙 전체를 지우지는 않는다

  • color: 두 규칙에서 경쟁하므로 나중 값인 초록색을 사용한다.
  • background와 border-width: 두 번째 규칙이 값을 지정하지 않는다.
    첫 번째 규칙의 파란 배경과 5px 테두리가 그대로 남는다.
  • 공통 모양 + 차이: 카드 공통 규칙에 여백·배경을 두고 상태 규칙에서 일부 속성만 바꾸는 이유이다.
.cascade-properties .card {
  color: #0057d9;
  background: #e4efff;
  border-width: 5px;
}
.cascade-properties .card { color: #11643a; }

<p class="card">초록 글자 + 파란 배경 + 5px 테두리</p>

초록 글자 + 파란 배경 + 5px 테두리

개발자 도구에서 첫 규칙의 color만 취소선이 나타난다.
같은 블록의 나머지 선언까지 무효가 된 것은 아니다.

명시도 읽기

점수 합계가 아니라 세 칸을 왼쪽부터 비교한다

명시도(specificity)는 선택자가 대상을 얼마나 구체적으로 지정하는지 비교하는 값이다.
출처·중요도·레이어가 같은 선언끼리 비교할 때 사용한다.

  • 첫째 칸 — ID: #menu 같은 id 선택자의 개수이다.
  • 둘째 칸 — class 계열: .active, [type="email"], :hover 같은 class·속성·일반 가상 클래스의 개수이다.
  • 셋째 칸 — 태그 계열: p, button, ::before 같은 타입 선택자·가상 요소의 개수이다.
  • 숫자가 늘지 않는 기호: 공백·>·+·~ 결합자와 전체 선택자 *는 명시도에 더하지 않는다.
  • 비교 방법: (1, 0, 0)은 (0, 20, 0)보다 높다.
    왼쪽 칸부터 비교하므로 class가 많아져도 id 한 개를 따라잡는 십진수 덧셈이 아니다.
  • 함수형 선택자 주의: :not(.sold-out)의 명시도는 내부 인수인 .sold-out에서 온다.
    :not() 자체를 하나 더 세지 않는다. :is()·:has()·:where()의 별도 규칙은 심화 범위이다.
선택자명시도 (ID, class, 태그)읽는 방법
p(0, 0, 1)타입 선택자 1개
.card:hover(0, 2, 0)class 1개 + 가상 클래스 1개
input[type="email"](0, 1, 1)속성 1개 + 타입 1개
#menu > a(1, 0, 1)ID 1개 + 타입 1개, >는 0

EXAMPLE 3

명시도가 높으면 더 먼저 작성한 규칙도 이길 수 있다

  • .cascade-specificity #priority-card: (1, 1, 0)이다. 가장 먼저 선언했지만 ID 칸이 높아 파란색이 된다.
  • .cascade-specificity .featured: (0, 2, 0)이다. 주황색 선언은 이기지 못한다.
  • .cascade-specificity p: (0, 1, 1)이다. 마지막에 있어도 초록색은 적용되지 않는다.
.cascade-specificity #priority-card { color: #0057d9; }
.cascade-specificity .featured { color: #9b3f00; }
.cascade-specificity p { color: #11643a; }

<p id="priority-card" class="featured">먼저 쓴 ID 규칙의 파란색</p>

먼저 쓴 ID 규칙의 파란색

이 결과는 “id를 많이 쓰라”는 뜻이 아니다.
필요 이상으로 명시도를 높이면 나중에 상태나 공통 테마를 바꾸기 어려워지므로, 기본 스타일은 짧은 class 선택자로 관리한다.

EXAMPLE 4

!important는 명시도가 아니라 선언의 중요도를 바꾼다

  • 일반 인라인 선언: 이 예제처럼 같은 작성자 출처의 일반 스타일시트 선언과 비교하면 인라인 style이 우선한다.
    첫 문단은 ID 선택자 규칙이 있어도 인라인의 주황색을 사용한다.
  • 중요한 선언: 두 번째 문단의 스타일시트에는 !important가 있다.
    같은 작성자 출처의 일반 인라인 선언보다 중요도가 높아 파란색이 된다.
  • 범위가 있는 설명: 인라인 선언도 !important를 가질 수 있고 사용자 스타일 등 다른 출처도 존재한다.
    따라서 “인라인은 항상 이긴다” 또는 “!important가 무조건 모든 것을 이긴다”라고 외우지 않는다.
  • 수정의 출발점: 적용되지 않는다고 즉시 !important를 붙이지 않는다.
    선택 대상·출처·중요도·명시도·작성 순서를 확인하고 불필요한 중복 선언을 정리한다.
.cascade-priority #inline-normal { color: #0057d9; }
.cascade-priority #inline-important { color: #0057d9 !important; }

<p id="inline-normal" style="color: #9b3f00">
  일반 인라인 선언 → 주황색
</p>
<p id="inline-important" style="color: #9b3f00">
  중요한 스타일시트 선언 → 파란색
</p>

일반 인라인 선언 → 주황색

중요한 스타일시트 선언 → 파란색

!important를 제거하면 두 번째 문단도 주황색으로 바뀐다.
이 표시는 예외를 비교하기 위한 것이며 이후 박스·Flex 예제의 기본 해결법으로 사용하지 않는다.

EXAMPLE 5

상속은 부모 값을 물려받는 것이지 부모 선택자와 경쟁하는 것이 아니다

  • 상속되는 속성: color, font-family 같은 글자 관련 속성은 보통 부모에서 자식으로 이어진다.
    첫 번째 span은 자신의 color가 없어 부모의 파란색을 물려받는다.
  • 직접 선언이 있는 자식: 두 번째 span은 자신의 color가 지정되어 주황색이다.
    부모 선택자의 명시도가 더 높더라도 자식의 직접 선언과 부모의 선언을 같은 요소의 경쟁으로 비교하지 않는다.
  • 상속되지 않는 속성: border, padding, margin은 기본적으로 상속되지 않는다.
    아래 점선 테두리는 부모 한 개에만 있고 각 span 주변에 복제되지 않는다.
  • 명시적인 상속: 필요하다면 color: inherit처럼 부모의 계산된 값을 사용하라고 선언할 수 있다.
    배경이 비쳐 보이는 현상은 background 상속과 다르다. 기본 배경이 투명해서 부모 배경이 보일 수도 있다.
.cascade-inheritance .parent {
  color: #0057d9;
  border: 4px dashed #0057d9;
}
.cascade-inheritance .direct { color: #9b3f00; }

<div class="parent">
  <span>부모에게 물려받은 파란색</span>
  <br>
  <span class="direct">직접 선언한 주황색</span>
</div>
부모에게 물려받은 파란색
직접 선언한 주황색

두 번째 span의 color를 개발자 도구에서 해제하면 부모의 파란색을 물려받는다.
이번에는 다른 형제의 색이 바뀌지 않는다.

개발자 도구

취소선을 읽으면 왜 적용되지 않는지 추적할 수 있다

  1. 대상 요소 검사: 위 예제의 카드에서 우클릭 후 검사를 선택한다. Elements 패널에서 실제로 선택한 요소가 맞는지 확인한다.
  2. Styles에서 속성 찾기: color를 검색하고 적용되는 선언과 취소선 선언을 비교한다.
    취소선은 다른 선언에 밀렸다는 단서이다. 잘못된 값은 경고 아이콘 등으로 표시될 수 있으므로 구분한다.
  3. Computed에서 최종값 확인: 화면에 사용된 최종 색상과 연결된 선언 위치를 확인한다.
    색상은 rgb(...)처럼 원래 작성한 표기와 다르게 보일 수 있다.
  4. 한 선언만 해제: 체크를 끄면 다음 우선순위 선언이나 상속값이 드러난다.
    개발자 도구에서 바꾼 내용은 보통 새로고침하면 사라진다. 유지할 수정은 원본 CSS 파일에 반영한다.

같은 요소·같은 속성의 선언 목록을 확인한 뒤 한 조건씩 비교한다.
원인을 찾았으면 박스 모델에서 그 선언이 실제로 차지하는 공간을 살펴본다.
