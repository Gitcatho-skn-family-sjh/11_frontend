HTML 03

영역의 이름이 읽는 길을 만든다

태그 이름으로 화면의 역할을 드러내면 다음 사람이 코드를 읽고 고치기 쉬워진다.

의미로 구분하기

같은 상자처럼 보여도 태그마다 맡은 역할이 다르다

시맨틱 태그는 모양을 정하는 장식이 아니라 각 영역의 목적을 코드에 남기는 이름이다.
화면을 위에서 아래로 읽으며 다음 네 역할을 구분한다.

  • header: 페이지나 특정 구역을 소개하는 제목과 안내를 묶는다.
    문서 맨 위에서만 쓰는 태그가 아니며, 필요한 구역 안에도 소개 머리말로 사용할 수 있다.
  • main: 현재 페이지에서 가장 중심이 되는 내용을 한 번 묶는다.
    반복 메뉴나 부가 정보가 아니라 사용자가 이 페이지를 연 핵심 목적을 담는다.
  • section: 같은 주제를 공유하는 내용을 제목과 함께 묶는다.
    단지 테두리를 만들기 위한 상자가 아니라 “오늘의 일정”처럼 하나의 주제 단위를 표현한다.
  • article: 일정 한 건이나 게시물처럼 따로 떼어도 의미가 통하는 독립 항목에 사용한다.
    여러 article이 한 section 안에서 같은 종류의 콘텐츠로 반복될 수 있다.

역할

상자를 그리기 전에 역할을 나눈다

header는 페이지나 구역의 소개를, main은 그 페이지의 핵심 내용을 나타낸다.
단순한 모양은 CSS로 바뀌어도 이 역할은 유지된다.

section은 하나의 주제로 묶은 내용이고, article은 혼자 떼어 읽어도 뜻이 통하는 항목이다.
이 구분은 나중에 JavaScript가 요소를 선택할 때도 도움이 된다.

EXAMPLE

강의 일정 화면을 실제로 읽기

<header><h3>웹 기초 강의</h3></header>
<main><p>오늘 핵심: HTML 구조 읽기</p></main>
<section>
  <h3>오늘의 일정</h3>
  <article>목록 만들기</article>
  <article>CSS 시작하기</article>
</section>
<footer>준비물: 브라우저</footer>

소개·핵심 문장·독립 일정이 서로 다른 태그로 나뉘는지 확인한다.
교안 자체의 main 안에 예제의 main을 중첩하지 않도록, 위 결과는 독립된 미리보기 문서에서 표시한다.

구체적인 반례

모든 구역을 div로 써도 화면은 보일 수 있다.
그러나 ‘오늘의 일정’과 한 건의 일정이 어떤 관계인지 코드만 보고 알기 어렵다.

EXAMPLE

nav는 이동 경로, section은 도착할 주제를 나타낸다

  • nav에는 주요 탐색 링크를 묶는다.
    모든 링크를 무조건 nav로 감싸기보다, 페이지 목차나 메뉴처럼 이동 경로 자체가 목적일 때 사용한다.
  • href="#morning-program"은 현재 문서에서 해당 id를 가진 요소로 이동한다.
    링크 문장은 사용자가 읽는 목적지 이름이고 id는 문서가 찾는 고유 식별자이다.
  • section은 오전·오후라는 주제를, 그 안의 article은 독립적인 일정 한 건을 표현한다.
    제목 수준도 이 관계에 맞춰 section의 h3 아래 article의 h4를 둔다.
<nav aria-label="일정 바로가기">
  <a href="#morning-program">오전 일정</a>
  <a href="#afternoon-program">오후 일정</a>
</nav>
<section id="morning-program">
  <h3>오전 일정</h3>
  <article><h4>기획 회의</h4><p>09:30, 회의실 A</p></article>
</section>
<section id="afternoon-program">
  <h3>오후 일정</h3>
  <article><h4>디자인 검토</h4><p>14:00, 회의실 B</p></article>
</section>
