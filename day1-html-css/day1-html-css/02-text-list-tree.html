HTML 02

글과 목록이 만드는 읽는 순서

제목·문단·목록은 정보를 위에서 아래로 이해할 수 있게 정리하는 HTML의 기본 단위이다.

텍스트부모와 자식

STRUCTURE

내용의 순서와 묶음을 태그로 표시한다

h1은 문서의 최상위 제목, p는 문단이다.
순서가 중요한 항목은 ol, 순서보다 묶음이 중요한 항목은 ul로 쓴다.

목록 안의 li는 부모 목록의 자식이다.
이 계층은 다음에 CSS 선택자와 DOM 트리를 읽는 기준이 된다.

  • h1과 하위 제목: h1은 문서 전체의 주제를 보여 주고 h2, h3는 그 안의 세부 주제를 단계적으로 나눈다.
    글자 크기를 고르기보다 내용의 계층을 기준으로 제목 수준을 선택한다.
  • p: 제목에 대한 설명을 문장 단위가 아니라 의미가 이어지는 문단으로 묶는다.
    새 주제로 넘어갈 때 문단을 나누면 화면과 소스 코드 모두 읽기 쉬워진다.
  • ol과 ul: 실행 단계처럼 앞뒤 순서가 중요하면 ol, 준비물처럼 같은 그룹이라는 사실이 중요하면 ul을 사용한다.
    화면 모양이 아니라 항목 사이의 의미 관계로 선택한다.
  • li와 트리: 각 li는 목록의 직접 자식이며 번호나 글머리표 하나가 된다.
    목록 안에 다시 목록을 넣으면 부모·자식 단계가 한 층 더 생기며 이후 CSS 선택자와 DOM 탐색의 기준이 된다.

EXAMPLE

이번 주 학습 계획

<h1>이번 주 계획</h1>
<p>작은 단위로 확인한다.</p>
<ol>
  <li>문서 골격 읽기</li>
  <li>목록 만들기</li>
  <li>CSS 시작하기</li>
</ol>

<ul>
  <li>공책 준비하기</li>
  <li>필기도구 챙기기</li>
</ul>

이번 주 계획

작은 단위로 확인한다.

  1. 문서 골격 읽기
  2. 목록 만들기
  3. CSS 시작하기
  • 공책 준비하기
  • 필기도구 챙기기

화면 해석

큰 제목 아래 문단이 보이고, 세 계획은 1·2·3 번호로 표시된다.
HTML에 적은 순서가 읽는 순서가 된다.

혼동하기 쉬운 점

ol 바로 안에는 문장을 쓰지 않고 li 항목을 넣는다.
번호를 직접 입력하는 것보다 구조를 유지하기 쉽다.

ORDER OR GROUP

순서가 의미를 가지는지 먼저 판단한다

조리 순서나 단계처럼 앞뒤가 바뀌면 뜻이 달라지는 목록은 ol을 사용한다.
준비물이나 관심 분야처럼 같은 묶음이라는 사실이 중요하면 ul이 알맞다.

브라우저가 번호나 글머리표를 자동으로 표시하므로 항목을 추가하거나 삭제해도 순서를 다시 입력할 필요가 없다.
CSS로 표시 모양이 바뀌어도 목록이라는 HTML 구조와 부모·자식 관계는 유지된다.

EXAMPLE

목록 안의 목록으로 부모·자식·후손을 구분한다

  • 하위 목록은 상위 ul 바로 아래가 아니라, 해당 항목인 li 안에 넣는다.
    여행 준비 전체와 그 안의 준비물 그룹이라는 의미가 중첩 구조에 남는다.
  • 바깥 ul의 직접 자식은 두 개의 li이다.
    여권과 충전기는 한 단계 더 안쪽에 있으므로 바깥 목록의 후손이지만 직접 자식은 아니다.
  • 들여쓰기는 사람에게 관계를 보여 준다. 실제 부모·자식 관계는 여는 태그와 닫는 태그의 위치가 결정한다.
    이 차이는 뒤에서 공백 선택자와 > 선택자를 비교할 때 다시 사용한다.
<ul class="travel-list">
  <li>교통편 예약</li>
  <li>준비물
    <ul>
      <li>여권</li>
      <li>충전기</li>
    </ul>
  </li>
</ul>
  • 교통편 예약
  • 준비물
    • 여권
    • 충전기

바깥 목록 항목은 2개, 문서 전체의 li는 4개이다.
“바로 아래 항목”과 “안쪽의 모든 항목”은 서로 다른 범위이다.
