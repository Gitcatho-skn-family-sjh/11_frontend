ONE HTML, TWO LAYOUTS

반응형 CSS는 같은 내용을 화면 조건에 맞게 다시 배치한다

모바일용 내용을 새로 만들지 않고 하나의 HTML과 읽기 순서를 유지한 채, 필요한 CSS 차이만 조건 안에서 덮어쓴다.

아래 코드에서는 배치 변화에 필요한 선언을 중심으로 표시한다.
실제 소스의 선택자 앞에는 예제 범위를 한정하는 .responsive-lesson이 추가되며, 색상과 테두리 같은 장식 규칙은 따로 제공되어 있다.

  • 기본 규칙: 미디어 쿼리 밖의 선언은 모든 화면에 먼저 적용된다.
    넓은 화면을 위한 가로 Flex, 간격, 카드 크기를 공통 출발점으로 둔다.
  • breakpoint: max-width: 700px은 CSS 화면 폭이 700px 이하일 때 변경 규칙을 적용한다.
    특정 휴대전화 이름이 아니라 내용이 답답해지는 폭을 기준으로 정한다.
  • 차이만 덮어쓰기: 좁은 화면에서는 flex-direction: column처럼 달라지는 속성만 다시 선언한다.
    나머지 색상과 내용 스타일은 기본 규칙을 그대로 이어받는다.
  • viewport와 읽기 순서: viewport meta가 있어야 모바일 브라우저가 실제 기기 폭으로 조건을 계산한다.
    시각적 방향이 바뀌어도 HTML 순서는 유지되어 키보드와 보조 기술의 읽기 흐름이 흔들리지 않는다.

CONTENT STAYS

반응형 화면은 내용을 삭제하지 않고 읽는 순서를 보존한다

넓은 화면에서는 표시 영역과 소개 문장을 나란히 두면 가로 공간을 효율적으로 쓸 수 있다.
같은 배치를 좁은 휴대전화에서 유지하면 문장이 지나치게 좁아지거나 페이지 밖으로 밀릴 수 있다.

반응형 CSS는 별도의 모바일 HTML을 만드는 방식이 아니다.
하나의 HTML을 유지하고 화면 조건에 따라 배치·간격·크기 규칙을 바꾼다.
내용과 DOM 순서가 같으므로 다음 JavaScript 수업에서도 같은 요소를 계속 선택할 수 있다.

EXAMPLE

1. 프로필의 가로 배치를 세로 배치로 바꾼다

미디어 쿼리 밖의 display: flex와 gap은 모든 화면에 적용되는 기본값이다.
@media (max-width: 700px) 안에서는 방향만 column으로 바꾼다.
공통 규칙을 반복하지 않아도 cascade가 필요한 차이를 덮어쓴다.

넓은 화면 기본값과 좁은 화면 변경값CSS
.profile-demo {
  display: flex;
  gap: 1.25rem;
  align-items: flex-start;
}

@media (max-width: 700px) {
  .profile-demo {
    flex-direction: column;
  }
}

@media (max-width: 700px) {
  .profile-mark {
    flex-basis: auto;
    width: 100%;
    max-width: none;
    aspect-ratio: auto;
    padding: 1.5rem;
  }
}

브라우저 창의 오른쪽 경계를 끌어 폭을 줄인다.
700px보다 넓을 때는 표시와 설명이 좌우에 놓이고, 700px 이하에서는 표시가 위에, 설명이 아래에 놓인다.

flex-direction: column으로 바뀌면 flex-basis는 가로가 아닌 세로의 기준 크기가 된다.
따라서 표시 영역의 기존 7rem 기준을 auto로 바꿔 고정 높이가 의도치 않게 남지 않도록 한다.

화면 폭 확인→700px 초과: row／700px 이하: column→같은 내용 재배치

EXAMPLE

2. 도구 모음은 좁은 화면에서 링크를 넓게 배치한다

넓은 화면에서는 제목을 왼쪽, 링크 묶음을 오른쪽에 놓는다.
700px 이하에서는 제목과 링크를 위아래로 배치하고 각 링크가 남은 폭을 나눠 쓰게 한다.

  • 부모 방향 변경: flex-direction: column으로 제목과 링크 묶음을 세로로 놓는다.
    프로필 예제와 같은 원리를 다른 화면 요소에 적용한다.
  • 교차축 변경: column의 교차축은 가로이므로 align-items: stretch가 링크 묶음의 폭을 늘린다.
    여기서 center를 유지하면 링크 묶음은 가운데에 좁게 모일 수 있다.
  • 내부 자식 크기: 링크 묶음은 별도의 Flex container이다.
    각 링크의 flex: 1이 같은 행의 여유 공간을 나누며, 부모와 손자의 Flex 관계를 구분해야 한다.
.rp-toolbar {
  display: flex;
  flex-wrap: wrap;
  justify-content: space-between;
  align-items: center;
  gap: 1rem;
}
.rp-actions { display: flex; gap: .5rem; flex-wrap: wrap; }

@media (max-width: 700px) {
  .rp-toolbar {
    flex-direction: column;
    align-items: stretch;
  }
  .rp-actions a { flex: 1; }
}

EXAMPLE

3. 내용에 따른 줄바꿈은 미디어 쿼리 없이도 가능하다

모든 크기 변화에 breakpoint를 만들 필요는 없다.
태그처럼 각 항목의 크기를 유지한 채 다음 줄로 보내면 되는 경우에는 flex-wrap만으로 공간에 적응할 수 있다.

  • 미디어 쿼리: viewport라는 화면 조건에 따라 다른 규칙을 선택한다.
    이 페이지에서는 700px 경계에서 가로와 세로 배치를 명시적으로 전환한다.
  • 자연스러운 줄바꿈: 항목이 부모 안에 들어갈 수 있는지를 보고 줄을 바꾼다.
    같은 화면 폭에서도 넓은 영역과 220px 영역의 줄 수가 다를 수 있다.
  • 너비 안전장치: max-width: 100%는 아주 긴 태그가 부모보다 커지는 것을 막는다.
    overflow-wrap: anywhere는 공백 없는 긴 문자열도 필요할 때 줄바꿈하도록 한다.
.rp-tags {
  display: flex;
  gap: .5rem;
  flex-wrap: wrap;
}
.rp-tags span {
  max-width: 100%;
  overflow-wrap: anywhere;
}
.rp-tags-narrow { width: min(100%, 220px); }

BREAKPOINT

700px 경계의 양쪽을 확인한다

max-width: 700px은 “700px 미만”이 아니라 “700px 이하”이다.
브라우저 개발자 도구의 반응형 화면에서 701px, 700px, 699px을 차례로 지정하면 경계를 분명하게 볼 수 있다.

  • 701px: 미디어 쿼리 조건이 거짓이다.
    프로필과 도구 모음에는 기본 row 방향이 적용된다.
  • 700px와 699px: 조건이 참이다.
    프로필과 도구 모음이 column으로 전환되고, 태그는 자신에게 주어진 공간에 맞춰 줄을 바꾼다.
  • 390px와 768px: 경계값만 통과했다고 끝내지 않는다.
    좁은 휴대전화 폭과 중간 폭에서도 내용 잘림, 가로 스크롤, 링크의 초점 표시를 확인한다.
  • 판정 기준: 여기서 700px은 demo 카드의 너비가 아니라 브라우저 viewport의 CSS 픽셀 너비이다.
    왼쪽 목차나 카드의 padding이 있어도 미디어 쿼리 조건은 viewport를 기준으로 한다.
현재 조건: 700px 초과 · 기본 row 규칙현재 조건: 700px 이하 · column 변경 규칙

VIEWPORT MATTERS

HTML의 viewport 설정이 실제 기기 폭을 CSS에 전달한다

<meta name="viewport" content="width=device-width, initial-scale=1.0">가 있어야 모바일 브라우저가 기기 화면 폭을 기준으로 레이아웃을 계산한다.
1교시부터 모든 문서에 이 줄을 넣은 이유가 여기에서 드러난다.

미디어 쿼리는 특정 기기 이름을 찾지 않는다.
현재 사용할 수 있는 CSS 화면 폭을 조건으로 삼는다.
700px은 절대적인 정답이 아니라 카드 내용이 답답해지기 시작하는 지점을 보고 선택한 경계값이다.

max-width 안에서도 계속 row라면 화면은 바뀌지 않는다

조건문을 썼다는 사실만으로 반응형이 되지 않는다.
조건 안에서 실제로 달라질 선언이 있는지, 선택자 이름이 기본 규칙과 같은지 확인한다.
